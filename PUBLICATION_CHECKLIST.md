# Public Portfolio Publication Checklist

- [ ] Confirm the public display name, degree, year and GitHub profile link are correct and approved for publication.
- [ ] Verify all newly published files contain no secrets, private project code, internal URLs, access tokens, proprietary research details or real user telemetry.
- [ ] Confirm RAI and CR repositories remain private; only high-level summaries are shown publicly.
- [ ] Run nine focused authentication detection tests and inspect expected output.
- [ ] Clearly label synthetic data, illustrative SPL and private architectural summaries.
- [ ] Verify case study links, mobile presentation and keyboard navigation.
- [ ] Enable GitHub Pages in Settings → Pages and verify the live URL after deployment.
- [ ] Add a professional email or LinkedIn URL only after deliberately approving public disclosure.
- [ ] Before claiming completed Splunk use, test the SPL in an authorized instance and publish sanitized evidence.

**No public security claims should exceed the evidence made available to support them.**
