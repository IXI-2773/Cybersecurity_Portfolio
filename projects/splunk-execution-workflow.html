The evidence contract

Source and event time
The expected lab contains 64 original rows and six new synthetic replay rows. Every native indexed timestamp must match its UTC source value before the detection query recalculates time. Duplicate or missing rows fail verification.
Detection parity
The historical input must still produce the same five expected findings. A source-level comparison binds each result to its account, IP, host and scenario.
Actual alert provenance
A preview cannot substitute for a fired-alert record. The associated job must expose the expected indexed SPL, matching owner/app ACL and the exact fresh replay finding. A generating query or another index cannot qualify.
Failure state
A failed recheck clears the earlier success state. Invalid connection settings, incomplete jobs, inconsistent row counts and unrelated alerts cannot produce a completed handoff.

What a completed run produces

After all evidence checks pass, the tool writes compared CSV exports, source and query hashes, native search-job references, a verification report and an analyst handoff. These are private run artifacts until reviewed; this page does not present a fabricated completed run.

Observations
Indexed source values, UTC timing, canonical findings and the fired job's replay result.
Alternative explanation
Legitimate user recovery can also produce repeated failures followed by success. A threshold match does not establish compromise.

Inspect the implementation

The offline suite challenges the critical failure cases: duplicate ingestion, incorrect indexed time, altered findings, missing native alert evidence, wrong query or namespace, artifact tampering and stale success after a failed attempt. It tests the verifier; it does not prove that Splunk ran.
