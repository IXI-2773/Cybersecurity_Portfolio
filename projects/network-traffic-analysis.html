Network Traffic Analysis & Threat Hunting

Reproduce 20 fully synthetic Ethernet/IPv4 packets, inspect DNS and HTTP behavior, and validate a bounded Python analyzer with 18 focused tests.

All three images are rendered from the reproducible synthetic PCAP observations. They are not Wireshark screenshots, live captures, or evidence of a real intrusion.

Investigation hypothesis

Can we recognize a cluster of failed DNS lookups and a POST to an unusual reserved hostname without assuming they prove malicious behavior?

Dataset and reproducibility

The fixture generator writes a genuine PCAP binary: 10 DNS packets (five question/reply pairs), 10 TCP/HTTP packets, plus both benign comparison traffic and candidate alerts. All source addresses and hostnames are fabricated and reserved for documentation.

Run locally

python projects/03-network-pcap/generate_fixture.py --output projects/03-network-pcap/synthetic_traffic.pcap
python projects/03-network-pcap/analyze_pcap.py projects/03-network-pcap/synthetic_traffic.pcap
python -m unittest discover -s projects/03-network-pcap -p 'test_*.py' -v

Findings

  • DNS: four NXDOMAIN replies in 36 seconds tied to the same client. Possible investigation under ATT&CK T1071.004, but not demonstrated tunneling.
  • HTTP: POST to collector.invalid/upload; a hypothetical review case under T1071.001, not evidence of exfiltration.

Verification

The PCAP is deterministic (SHA-256 is recorded in the runbook). The 18 focused tests include expected findings, malformed capture rejection, deduplication, source isolation, DNS pairing, and benign HTTP/DNS controls.

Limits

This parser does not reassemble TCP streams or analyze TLS, pcapng, fragmented IPv4, compressed DNS names or IPv6. Wireshark manual inspection and authentic application screenshots remain pending. The illustrated evidence above is based on offline packet analysis. It is not a production intrusion-detection system.
