Engineering decisions that matter

  1. Keep time interpretation explicit.

    The preparation step mapped the export's two observed Pacific time labels to -07:00 and -08:00. The raw export stayed intact. This is a bounded transformation, not a general timezone detector.

  2. Preserve identity and sequence boundaries.

    Authentication joins stay within user, host and IP. A success resets preceding failure history; an equal-time failure cannot establish an order before success.

  3. Make incomplete evidence visible.

    The importer preserves rejected records and reports partial processing when appropriate. This 70-event run had no rejections and no rows coalesced as duplicates. Those counts do not establish upstream uniqueness or detection accuracy.

  4. Keep output safe to inspect.

    Log text is escaped in HTML; commands and URLs from input are inert. The tool does not execute response actions or overwrite an existing output directory.

Code and reproducible examples

Methodology and scope

Synthetic authentication events were processed through a running, owner-operated Splunk Enterprise instance and exported through its authenticated CLI. Development and validation were AI-assisted. This demonstrates an export-to-case workflow, not production incident response, continuous SIEM ingestion, detection accuracy or measured time savings.

The earlier scheduled-alert demonstration is separate. The six candidates here are Python triage outputs, not six fired Splunk alerts. No replay, reindexing or alert-schedule change was needed for this export-to-case run. No account was disabled, endpoint isolated or external notification sent.
