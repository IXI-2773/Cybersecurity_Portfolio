What the tool does

Reads bounded local CSV/JSON exports, resolves declared field aliases, requires timezone-aware timestamps and normalizes to UTC. It retains exact input-file hashes, parsed-record hashes and row references. The process-pattern checks reuse the repository's existing inspector.

Declared host/event IDs control deduplication. Conflicting IDs quarantine all matching rows; records without stable IDs remain distinct. Authentication joins preserve user, host and IP boundaries. Equal-time failures cannot establish an order before success.

The output is a portable HTML handoff plus machine-readable JSON. Log text is escaped in HTML, commands and URLs are inert, and existing output directories are never overwritten.

Run it yourself

Python 3.11+ and a clone of this repository are enough. This exported-log version needs no home PC connection, account, endpoint agent or Splunk instance. Choose a new output directory.

python projects/10-soc-triage/triage.py \
  projects/10-soc-triage/fixtures/authentication.csv \
  projects/10-soc-triage/fixtures/processes.json \
  --output-dir soc-triage-case

The sample returns exit code 2: partial processing with rejected records. Exit 0 means complete processing under the supported schema; exit 1 is a fatal input or I/O error. None is a security verdict.

Scope and limits

Completed offline tool with an executed synthetic-data walkthrough. It does not collect endpoint telemetry, connect to a SIEM, execute input commands or perform response actions. Authentication and process matches are review candidates; authorized activity can match.

This is a bounded export schema, not a universal vendor parser. Source rows can be incomplete or misleading; six deliberate rejections make this sample partial. No production incident, accuracy rate, time saved or autonomous containment is claimed. The separate live Splunk workflow remains pending.
