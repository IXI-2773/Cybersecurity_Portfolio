The investigation

I analyzed OTRF’s recorded PurpleSharp Active Directory emulation, built a reproducible Python analyzer, and tested detection logic against source records and counterexamples. The work links native process GUIDs and logon sessions to time-bounded network context.

The original capture was recorded by OTRF in 2020. This is my independent analysis of that public evidence, with the producer’s scenario notes kept separate from what the records establish.

Inspect detector logic and evidence boundaries

Failures: ≥5 distinct targets in 15 seconds, grouped by host/caller/PID/session. Tickets: ≥5 distinct successful RC4 services in 15 seconds. Shares provide context. Remote execution requires same-host parent GUID, account and session.

Security EventTime uses an inferred UTC−04:00 offset calibrated against 24 Sysmon process-start pairs. Security timestamps retain second precision. The PCAP parser inspects bounded headers and complete request lines in individual packets; it does not reassemble streams or decrypt content.

The strongest joins

On each target, Sysmon parent ProcessGuid identifies wsmprovhost.exe as the PowerShell parent. The account and logon ID also match the target’s Security 4624 type 3 logon. These direct host joins are stronger than matching a process name or PID alone.

Outgoing client Sysmon 3 events carry the original PurpleSharp ProcessGuid. Their exact TCP tuples match WSMan request packets. Target account, host and time associate that traffic with execution, but there is no end-to-end request ID proving which packet caused a particular PowerShell child.

Why collection time changes the story

The DC child executed at 08:29:58.095 UTC and was collected at 08:30:37.907 UTC: a 39.812-second delay. Switching clocks reveals how collection order can create a misleading second wave. Raw timestamps and the explicit conversion policy stay attached to every host excerpt.

Challenge the interpretation

Authorized WinRM administration produces the same parent/child tree. Legacy services can legitimately request RC4 tickets. The seven failures are local LogonType 2 events with no client IP; they support a distinct-account failure pattern, without proving a remote spray or a common password.

The analyzer retains twelve nonmatching ticket events. Tests change packet ports and remove target logons: execution findings remain, while full corroboration is withheld. These checks test the joins; one recorded emulation cannot establish enterprise precision, recall or a false-positive rate.

Inspect and reproduce

All 25,993 host records are counted; analysis selects 226 records from six event types. The network decoder accounts for all 1,121 packets, including 73 excluded records. Browser packet excerpts cover only the remote findings.
