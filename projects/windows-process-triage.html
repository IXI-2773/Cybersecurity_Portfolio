04 / HANDS-ON DEFENSIVE SECURITY LAB

Authentication Detection & Triage

A reproducible Windows Event ID 4688 triage exercise that flags command-line patterns requiring analyst review.

Python standard library11 focused testsSynthetic Windows eventsATT&CK mapping

Investigation question

Which Windows process creations contain command-line patterns worth reviewing? This exercise examines fabricated Windows Security Event ID 4688 records.

Detection hypotheses

  1. PowerShell with encoded-command switches → ATT&CK T1059.001.
  2. Certutil using URL-cache and force flags together → ATT&CK T1105.

Neither pattern alone proves malicious intent.

Run the lab

python -m unittest discover -s projects/02-windows-process-triage -p 'test_*.py' -v
python projects/02-windows-process-triage/process_triage.py projects/02-windows-process-triage/events_4688.csv

Expected output: 11 focused tests and two fabricated triage findings with timestamp, rule identifier, host, account, image, parent image, and process ID.

What was tested

Matching and nonmatching PowerShell invocations, alternate PowerShell image, legitimate certutil hashing, download-style certutil flags, invalid timestamps, unsupported event ID, malformed process ID, and stable event ordering.

Analyst response

  1. Verify process origin, signer, account, parent process and neighboring activity.
  2. Correlate with authorized PowerShell Script Block, EDR and endpoint telemetry.
  3. For certutil findings, review network and resulting file evidence.
  4. Compare against an approved administration baseline before escalation.

Scope and limitations

This tool never collects real Windows logs, executes commands, scans systems, or accesses a network. Command-line matching is simplistic and may generate false positives or miss obfuscated patterns. No enterprise detection-performance claim has been established.
