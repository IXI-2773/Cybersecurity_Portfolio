What the saved result shows

In the fabricated IPv4 filter/INPUT policy, two earlier DROP rules cover 75% of the IPv4 source space. A later rule still permits TCP/3389 from the remaining range within the tool's simplified model.

  1. Baseline: two review findings. UNRESTRICTED_ADMIN_SOURCE (HIGH) marks the rule's broad stated source. PARTIALLY_SHADOWED_RULE (INFO) identifies earlier terminating rules that overlap some, but not all, of its matches. Inspect the actual report.
  2. Proposed follow-up: zero modeled findings. Restrict the later TCP/3389 allow to 192.0.2.0/24, a documentation-only example subnet, and run the same offline analysis. This does not prove the configuration would be safe or reachable in production. Inspect follow-up JSON ↗.

How I approached it

I built a bounded offline reviewer for supported JSON and IPv4 iptables-save rules. It accounts for first-match terminating actions, individual and combined rule shadowing, and partial overlap. The output keeps rule identifiers and earlier-rule references attached to findings.

The key distinction: overlapping earlier drops do not make a later broad allow harmless. Partial overlap is informational; the broad-source review candidate remains visible for an analyst to assess.

Scope and limits

No live firewall, host, external network, or real organizational subnet was examined or changed. Both exports are synthetic. These are static review candidates, not confirmed vulnerabilities or measured exposure. The model does not establish IPv6, NAT, routing, connection state, or other unmodeled chains.

A production change would require an owner-approved source range, change control, validation of dependent access, and a rollback plan. Zero modeled findings is not a claim of secure deployment.
